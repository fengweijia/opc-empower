# OPCV2.0 全局重构工程设计规范 (Final Web-First Spec)

## 1. 架构愿景：统一的“AI赚钱军师”
基于与用户的深度探讨，我们确立了本次重构的核心基调：**极简、直接、单点突破**。
放弃复杂的表单和多Agent认知负担，放弃小程序的审核限制。以 Web-First (Next.js/React) 为载体，打造一个像 Claude 一样流畅的单一对话界面。

### 1.1 核心转变 (The Pivot)
*   **真实痛点聚焦**：针对“有硬技能但没有销售意识”（如40岁资深程序员）的独立开发者，提供直接能带来咨询和成交的“武器”。
*   **交互极简主义**：**No Forms (无表单)**。上来只有一个输入框：“你做了一个什么东西？” -> 回车 -> 惊艳的卖货文案。
*   **统一UI架构**：底层依然是直复式营销（文案、策略、流程、成交）的逻辑，但表层完全隐藏，化作一个统一的 Chat UI。
*   **技术栈大换血**：从 Taro(微信小程序) 转向 **Next.js (Web/H5)**，以支持极速开发、完美响应式、以及核心的 **SSE (Server-Sent Events) 流式输出**体验。

## 2. 系统架构重构方案

### 2.1 表现层 (Presentation Layer - Next.js)
*   **Unified Chat UI**：主界面仅为一个流式对话窗口。
*   **富文本与卡片渲染**：支持 Markdown 流式渲染，当 AI 输出特定结构时，渲染为交互卡片（如“一键复制”文案卡片、“一键生成落地页”按钮）。
*   **无感反馈机制**：摒弃繁琐的评价表单。通过记录用户的“复制”动作、或者卡片底部的轻量级“👍/👎”收集隐式数据。

### 2.2 调度层 (Orchestration Layer - Node.js Express)
*   **统一入口 `/api/chat`**：处理所有前端请求，支持流式返回。
*   **意图识别与隐式路由 (Intent Router)**：基于用户的自然语言，后端自动判断应该调用哪个底层 Prompt（文案生成？受众分析？异议处理？）。
*   **上下文注入**：自动维护会话历史，将用户的产品信息在多轮对话中逐渐补全并作为系统级 Prompt 注入。

### 2.3 核心 Agent 层 (单点突破：文案先行)
初期不再平行推进 4 个 Agent，而是**死磕“文案转化”这一单点**。
*   **Copywriting Engine**：注入“痛点、利益点、好奇心钩子、社会证明”的直复式营销核心 Prompt。
*   **反向推导能力**：当用户只输入“我写了一个自动化脚本”，AI 必须能穷举出 3 种目标客户画像供用户选择，而不是让用户自己填。

### 2.4 数据追踪与进化层 (Evolution Layer)
*   建立简单的 `Record` 表（如 SQLite/PostgreSQL 或简单的 JSON 文件系统），记录用户的 Input 和生成的 Output。
*   将高分文案自动沉淀为 Few-shot examples 喂给下一次生成的 Prompt。

## 3. 关键重构任务分解

### Phase 1: Web 基础设施搭建 (Web Infra)
*   初始化 Next.js + Tailwind CSS + shadcn/ui 项目（替代原有的 frontend Taro 项目）。
*   搭建极简的 Chat 界面骨架（输入框、消息列表）。

### Phase 2: 后端流式服务改造 (Backend SSE)
*   重构 `backend/index.js`，引入 SSE (Server-Sent Events) 支持，使大模型回复能够像打字机一样逐字显示。
*   实现统一的 `/api/chat` 路由，对接大模型服务。

### Phase 3: 核心交互与 Prompt 植入 (Core Chat & Prompts)
*   植入“反向推导客户画像”和“直复式营销朋友圈文案”的超级 Prompt。
*   实现前端 Markdown 渲染和定制化“文案卡片”（带复制按钮）。

### Phase 4: 上线与本地测试闭环 (Deployment & Test)
*   打通前后端本地联调，确保用户输入一句话，3秒内开始流式输出高质量文案。
*   撰写新的本地运行指南。
